# Integrator interface and conventions

The linear time steppers use the common call signature:

```python
new_state = integrator(state, time, step_size, linear_rhs)
```

Here `linear_rhs(state, time)` returns the time derivative generated by a
linear operator. For an equation written as

$$
\frac{d}{dt}\Psi(t)=L(t)\Psi(t),
$$

the callback returns `L(t) @ state`. For the time-dependent Schrödinger
equation,

$$
i\frac{d}{dt}\Psi(t)=H(t)\Psi(t),
$$

the corresponding callback is:

```python
def linear_rhs(state, time):
    return -1j * apply_hamiltonian(state, time)
```

This convention is shared by `CrankNicolson`, `ShortIterativeLanczos`, and
`ArnoldiExponential`.

For imaginary time, the evolution equation is
`d Psi / d tau = -H(tau) Psi`, so the callback returns `-H @ state`.
`CrankNicolson` and `ArnoldiExponential` consume that derivative directly.
`ShortIterativeLanczos` additionally needs `generator_factor=-1.0` so it can
recover the Hermitian Hamiltonian used to construct the Lanczos projection.
Its default `generator_factor=-1j` retains the real-time convention.

## State arrays

States may have any nonempty NumPy-compatible shape. The integrators preserve
that shape when calling the supplied operator. Input states are validated and
copied as needed; a time step does not modify the caller's input array.

The operator must return a finite numeric array with exactly the same shape.
Real inputs remain real when both the algorithm and the returned derivative
permit real arithmetic. A complex derivative promotes the propagated state to
complex arithmetic.

## Time-dependent operators

`CrankNicolson`, SIL, and SIA evaluate the linear operator at the temporal
midpoint. For an interval from `time` to `time + step_size`, the evaluation
time is:

```python
time + 0.5 * step_size
```

This provides a second-order approximation for a genuinely time-dependent
linear generator. Krylov convergence tolerances control the projected
exponential action; they do not estimate this midpoint time-discretization
error.

## Division of responsibilities

An integrator advances the supplied state. It does not:

- normalize a wavefunction;
- decide which observables to sample;
- construct a Hamiltonian;
- select a spatial representation;
- apply an absorbing mask after the step;
- decide whether a CAP is physically appropriate.

Those policies belong to the calling package. A CAP is part of the operator
action and makes the effective Hamiltonian non-Hermitian, which affects the
choice between SIL and SIA.

In particular, an imaginary-time Krylov step intentionally returns the
unnormalized exponential action. Normalization, orthogonalization against
previously found states, symmetry-sector selection, and ground-state
convergence tests belong to the calling application.

## Compound algorithms

`Strang2`, `IMCMF1`, and `IMCMF2` receive stepper objects obeying compatible
call conventions. This permits, for example, a Krylov exponential method to
be used as a linear substep when the mathematical assumptions of that
composition are satisfied.
